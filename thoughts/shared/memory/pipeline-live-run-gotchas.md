Load-bearing facts for running the live Dagster pipeline (the 2026-06-23 incident + first real end-to-end run on two Craig sessions, 2026-6-18 / 2026-6-22).

**Cascade-sensor backlog ADOPTION (the re-enable-without-seed solution).** The three sensors detect "new" work as `files-on-disk − registered-dynamic-partitions`. Enabling a sensor whose input dir holds migrated-at-rest history therefore treats all of it as new → mass reprocessing (the incident: `linguist_output_sensor` swept the 42 committed `apps/linguist/transcripts/*.txt` → 42 PAID mouthpiece runs). Fix = one-time **adoption** keyed on the sensor cursor: on first eval (`context.cursor is None`) register the existing sessions as partitions but emit NO run requests, then stamp the cursor (`"adopted"`); only sessions appearing *after* adoption run. The cursor lives in the Dagster Postgres instance and **persists across redeploys** — so adoption happens once. Applied ONLY to `linguist_output_sensor` (its input has the 42 seed); `scribe_output_sensor` needs no guard because `apps/scribe/data/saved/` is seed-free by construction (history was loaded straight into linguist, never through scribe). All three sensors are `default_status=RUNNING`. To deliberately reprocess history later, it's a manual backfill, not a sensor sweep.

**scribe → Groq Whisper constraints (Decision G path; faerrin used whisperx so no port).** A single degenerate Craig per-user track (a user who barely spoke) was failing the whole session four different ways — each fixed in `apps/scribe`: (1) skip voiced **spans** < `min_chunk_sec` (0.1s); (2) the *cut* flac can be far shorter than its span (`chunk_args` uses `-ss` input-seek which keyframe-snaps/overshoots near EOF), so **probe the actual flac** and skip < 0.1s, plus a backstop `except "too short"` around the Groq call; (3) ffprobe prints `"N/A"` for a degenerate clip's duration → parse defensively (`float()` in a try, → 0.0); (4) Groq's **direct-upload cap is ~25 MB** (the 100 MB tier is URL-only) → 413 "Request Entity Too Large" on long chunks — fixed by forcing `-sample_fmt s16` in `chunk_args` (flac is lossless = raw ceiling, 16 kHz mono s16 = 32 KB/s) AND `max_chunk_sec` 1200→480, a HARD ≤ ~14.6 MiB per chunk regardless of content.

**Transient provider resilience (unattended pipeline).** A sensor won't re-fire an already-partitioned session, so a transient external failure strands it. Two layers: `libs/py/llm` `_default_completion` sets litellm `num_retries=5` (rides ~30s of Anthropic 529 "Overloaded" → InternalServerError); and the mouthpiece external-API assets (`session_digest`, `session_script` = Anthropic; `session_audio_clips` = ElevenLabs) carry a Dagster `RetryPolicy(max_retries=3, delay=120, backoff=EXPONENTIAL)` to ride a *sustained* multi-minute outage (~14 min). The local ffmpeg `session_episode` has none. See [[deploy-sops-injection]], [[telemetry-built-in]].

**Re-running a failed pipeline partition.** Use GraphQL `launchRunReexecution` against the webserver (`localhost:10350`); `strategy: ALL_STEPS` restarts the run, `FROM_FAILURE` resumes at the failed step reusing completed upstream artifacts (digest/script are written to `apps/mouthpiece-backend/episodes/<date>/` so FROM_FAILURE skips the paid LLM stages). The `craig_drop_sensor` will NOT re-fire a session whose scribe partition already exists/failed — re-execute it explicitly.

**ElevenLabs gotcha:** the TTS 401 was **out of credits**, not a bad key. Don't validate the ElevenLabs key with `GET /v1/user` — the scoped pipeline key lacks the `user_read` permission so that endpoint 401s (`missing_permissions`) even when the key is fine for `text-to-dialogue`. Once credits were topped up, a `launchRunReexecution` FROM_FAILURE on the two mouthpiece partitions resumed at `session_audio_clips` (reusing the cached digest/script — no LLM re-spend) and completed.

**Tracking new linguist outputs (host-side, NOT a Dagster step).** `apps/linguist/transcripts/*.txt` + `apps/linguist/data/*.json` (minus the gitignored `*.candidates.json`) are tracked source-of-record; scribe audio + mouthpiece episodes are gitignored binaries. New pipeline output is auto-committed by a **host-side** `just linguist-commit` recipe + systemd user timer (`deploy/systemd/linguist-commit.{service,timer}`, every 15 min) — NOT a Dagster step, because the run containers have no `.git` (only the `transcripts`/`script`/`data` subdirs are bind-mounted, `/repo` is a baked COPY). Mirrors the craig-sync timer. Scoped `git add` of those two dirs, `--no-verify` (data-only; the biome/ruff pre-commit gate needs bunx/uv which the user-service PATH lacks), commit + push to origin/main. Push works unattended because the host's `~/.ssh/id_ed25519` is passphraseless (the user-systemd env has no SSH_AUTH_SOCK). Install once: `just linguist-commit-timer-install`.

Per-step models: scribe=Groq whisper-large-v3; linguist judge=claude-haiku-4-5 → escalate claude-sonnet-4-6; mouthpiece distill/script/mega=claude-opus-4-8; TTS=ElevenLabs `eleven_v3`; episode assembly + transcript application = no model.

**akasha-frontend auto-redeploys on new transcripts (`079c045`).** The `linguist-commit` timer now, after committing+pushing, rebuilds+redeploys akasha-frontend (`cd deploy && docker compose up -d --build akasha-frontend`) iff this run changed `apps/linguist/{transcripts,data}` — akasha reads that dir at build time, no secrets, failed build leaves the running container up. **akasha cutover gates were loosened** (`ed3c561`): the pipeline is live so content GROWS past faerrin's 217 — `urlParity`/`transcriptParity`/`build-content` tests now assert "no faerrin slug lost + no dups + extras are well-formed new `Script/` pages", counts are floors (`>=217`/`>=76`), not exact. **mouthpiece-frontend live-pipeline integration — COMPLETE + LIVE-VERIFIED** (`a472d54`…`7c25d2f`, 2026-06-23). The frontend now shows the full corpus (7 historical ∪ 2 live), auto-publishing as the pipeline produces more. The load-bearing facts, by the 5 steps:

1. **Layout fix (`a472d54`).** The pipeline keys its Dagster partition (+ on-disk dir) by **date** (`episodes/2026-6-22/`) but `assemble_episode` names audio/transcript by the **episode id** (`000.through-a-song-darkly.2026-6-22.episode.mp3`). `discover_sessions` keyed on the **dir name** → looked for `2026-6-22.episode.mp3` → `has_audio=False`, date-shaped id. Fix = read the id from the script (`session_id` astra snake_case / `sessionId` faerrin wire; dir name fallback) — the true id is in every `script.json`. The existing `<id>.episode.mp3` lookup then resolves for both date-keyed live AND id-keyed golden/seed dirs. Golden `sessionId` == its dir name, so the golden snapshot stays byte-identical.
2. **Catalog union (`1221d99`).** faerrin's **full** back-catalog (9 episodes, incl. 6-18/6-22) lives in `pkg/caster/out` as a **flat** `<id>.{script,digest}.json` store (the golden fixtures were just a 7-subset). New `astra_mouthpiece.migrate` (`just mouthpiece-migrate-history`) copies historical script+digest into id-keyed `episodes_path/<id>/`, **skipping ids astra already has** (live-precedence — astra's own renders win for any date both produced; idempotent). Audio is **decoupled** so the catalog copies only the tiny JSON (no mp3): the frontend renders `/audio/<id>.mp3` for EVERY episode regardless of `has_audio` (`audioVersion` is only an optional `?v=` cache-bust; `durationMs` comes from the Player's loadedmetadata, D5). `_dedup_by_id` in `build_index` (prefer audio, then more turns) is the order-independent safety net.
3. **Audio seed (`2409921`).** `just mouthpiece-seed` now gathers TWO sources in order: faerrin historical (flat) first, then astra's own `episodes/<date>/<id>.episode.mp3` (nested) which OVERWRITES for any date both produced (live wins, matches the dedup). 9 mp3s in `astra-mouthpiece-audio`; 6-18/6-22 are astra's renders (21.2/17.8 MiB), not faerrin's.
4. **Snapshot repoint + content-agnostic gates (`5f370a1`).** New `astra_mouthpiece.publish` (+ shared `build_episodes_index` extracted from the asset) regenerates the committed `snapshot/episodes-index.json` from the live corpus → **9 episodes**. The byte-equality freshness gate is gone (live has no in-git source); `test_episodes_snapshot` now validates shape + no-dups + sorted + **superset of the in-git golden baseline** (counts are a floor — akasha's posture). Frontend `build-content.test` count → `>=7`; the "recap last" assertion became "exactly one recap" (live sessions sort AFTER the 6-8 recap, whose `dateSortKey` derives from ~6-8).
5. **Auto-publish hook (`7c25d2f`).** The host-side `linguist-commit` timer gained a mouthpiece phase: run `just mouthpiece-publish` (migrate + publish), and on a snapshot change make its own commit + push + `mouthpiece-seed` + redeploy `mouthpiece-frontend` — each non-fatal. Deterministic, so a **no-op until a new episode lands** (verified: re-publish leaves the snapshot byte-identical). The snapshot must be regenerated **on the host** (the dagster container bind-mounts `episodes/` but NOT the committed `snapshot/` dir, and is a baked repo COPY). The user timer's PATH lacks uv → `uv_bin` absolute (`/home/jbassin/.local/bin/uv`) + nested recipe calls use `{{just_executable()}}`.
