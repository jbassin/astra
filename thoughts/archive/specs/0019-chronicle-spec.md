## 1. Overview

Add a new section to **akasha** (the wiki read-surface) presenting an **automatically structured,
in-depth timeline of the actual-play campaigns**, as a TV-guide hierarchy:

```
Show (campaign)  →  Season (GLM-5.2-derived)  →  Episode (one recorded session)
```

GLM-5.2 summarizes each session transcript into a Rich episode entry and groups a show's episodes
into seasons. The structuring is wired into the Dagster pipeline so new sessions flow in
automatically; the result renders at **`/chronicle`** in akasha-frontend.

This NLSpec assumes the verified facts and **resolved decisions** in the scope doc. There are **no
open questions**.

## 2. Actors

- **Reader** — visits `/chronicle`, browses shows → seasons → episodes, clicks an episode through
  to its existing transcript page.
- **The pipeline** (Dagster) — generates episode summaries + season groupings automatically as
  sessions are processed by linguist.
- **The linguist-commit timer** — commits generated chronicle artifacts and redeploys
  akasha-frontend.
- **The maintainer** — runs the one-time backfill of the 44 existing sessions.

## 3. Data model

### 3.1 `EpisodeSummary` (GLM output, Pydantic in `apps/linguist`)
Rich per-episode entry, produced via `LiteLLMClient.call_structured(EpisodeSummary, model=<GLM>)`:

| field | type | notes |
|---|---|---|
| `title` | `str` | GLM-authored episode title (evocative, ≤ ~80 chars) |
| `synopsis` | `str` | 2–3 sentences |
| `key_beats` | `list[str]` | ordered in-episode mini-timeline (~4–10 beats) |
| `characters_present` | `list[str]` | named PCs/NPCs (plain strings; v1 no wiki links) |
| `locations` | `list[str]` | plain strings |
| `factions` | `list[str]` | plain strings |
| `items` | `list[str]` | items / macguffins of note |
| `cliffhanger` | `str` | the hook/where it left off (may be empty) |

Carried metadata (not GLM-authored, stamped by the asset): `date` (session date string), `show`
(slug from the `transcripts/` filename prefix), `episode_number` (assigned later by the aggregate).

### 3.2 `SeasonStructure` (per show, GLM output)
Produced by the aggregate asset feeding each show's **ordered compact summaries** (title + synopsis
+ beats — not full transcripts) to GLM-5.2:

| field | type | notes |
|---|---|---|
| `seasons` | `list[Season]` | ordered |

`Season`: `{ number: int, title: str, arc_summary: str, episode_dates: list[str] }`.

### 3.3 Committed artifacts (storage = `apps/linguist/timeline/`)
- `apps/linguist/timeline/episodes/<date>.json` — one `EpisodeSummary` (+ metadata) per session.
- `apps/linguist/timeline/seasons.json` — `{ shows: [ { show, name, episodes_first_date,
  seasons: SeasonStructure } ] }`, shows ordered **main-first then by first-session date**, with
  per-show `S#E#` episode numbers resolved.

### 3.4 Show taxonomy (verified, fixed)
Show slug derives from the `transcripts/<NNN>.<show>.<date>.txt` filename prefix (1:1 to `being.kdl`
campaigns). Display name from `being.kdl` `campaign "<slug>" { name "..." }`. `through-a-song-darkly`
is the pinned main show.

## 4. Behaviors

- **B1** Each new session, after `session_transcripts` materializes, automatically gets an
  `EpisodeSummary` generated by GLM-5.2 and committed.
- **B2** Whenever episode summaries change, the season grouping is regenerated per show (GLM-5.2),
  producing `seasons.json` with stable `S#E#` numbering (by date within show).
- **B3** `/chronicle` lists all 7 shows (main-first, then by first-session date), each with episode
  count + season count.
- **B4** `/chronicle/<show>` renders that show's seasons (each: number, title, arc_summary) with
  episode cards beneath (S#E#, title, date, synopsis, key beats, entities, cliffhanger).
- **B5** Each episode card links to the existing transcript page `Script/<campaign>/<date>`.
- **B6** A nav entry "Chronicle" is reachable from the akasha shell.
- **B7** Generated chronicle artifacts are auto-committed and trigger an akasha-frontend redeploy
  (the timer extension).

## 5. Constraints / invariants

- **C1 — config-single-source.** Model id resolves from `astra_config` (`llm.default-model`,
  GLM-5.2). No hardcoded model/provider/paths. If a `linguist.chronicle-model` override is added,
  mirror it in **both** the py and ts config schemas; default it to `default-model`.
- **C2 — LLM lib only.** All GLM calls go through `astra_llm.LiteLLMClient.call_structured`
  (forced-tool typed output). **Not** the dspy judge (wrong task — see scope doc). Cost is
  auto-traced via `astra.llm.cost_usd`.
- **C3 — telemetry from day one.** Both assets emit spans + Dagster metadata (episode count, token
  cost surfaced from the client). The dagster code location already calls `init_telemetry`.
- **C4 — seasons never cross shows.** Grouping is strictly within a single show.
- **C5 — link, don't duplicate.** Episodes link to existing transcript pages; the chronicle does
  not re-render transcripts.
- **C6 — no silent scope cuts.** The full Rich `EpisodeSummary` and all 7 shows ship in v1.
- **C7 — port faerrin where applicable.** Grep faerrin for any prior recap/episode-summary tooling
  before writing new code; port its function if present.
- **C8 — atomic writes.** Use the linguist `_atomic_write` helper for artifact writes.
- **C9 — determinism for the gate.** `campaign_timeline` is deterministic given the same episode
  inputs except for the GLM season call; cache/skip when inputs unchanged so the timer is a no-op
  until a new episode lands.

## 6. Implementation slices (each independently CI-green, conventional-commit per slice)

> Reproduce both CI lanes locally before pushing; push when the chunk is done; do not watch GHA.

**S1 — data models + show map (py).** `EpisodeSummary`, `Season`, `SeasonStructure` Pydantic
models; a `show_for_date()` resolver from the `transcripts/` filename prefix; unit tests over real
filenames. No LLM. *Gate: `uv run pytest` green; ruff + ty clean.*

**S2 — `session_episode_summary` asset (py).** Partitioned-per-date asset, `deps=[session_transcripts]`,
reads `data/<date>.json`, builds the GLM prompt, `call_structured(EpisodeSummary)`, stamps metadata,
`_atomic_write` to `timeline/episodes/<date>.json`. Inject a stub completion in tests (judge pattern)
— **no real key in tests**. Register in `dagster/definitions.py`; extend the existing sensor's
RunRequest so new sessions also materialize this asset. *Gate: asset unit test with stubbed LLM;
pytest green.*

**S3 — `campaign_timeline` aggregate asset (py).** Reads all `timeline/episodes/*.json`, groups by
show, orders shows main-first then by first-session date, assigns `S#E#`, calls GLM-5.2 per show for
season assignment, writes `timeline/seasons.json`. Deterministic skip when inputs unchanged (C9).
Tests over fixture summaries with a stubbed LLM. *Gate: pytest green; produces a valid `seasons.json`.*

**S4 — backfill the 44 sessions.** Run inside the **dagster-code container** (root-owned write
path) — materialize `session_episode_summary` over all existing partitions, then `campaign_timeline`
once. Verify cost in SigNoz (~$2.30 expected). Commit the generated artifacts. *Gate: 44 episode
files + `seasons.json` present and well-formed.*

**S5 — frontend generated module (ts).** Extend `apps/akasha-frontend/scripts/build-content.ts` to
read `apps/linguist/timeline/{seasons.json,episodes/}` → emit `src/generated/chronicle.ts` (typed
shows→seasons→episodes, with the `Script/<campaign>/<date>` link per episode). A build-content test
asserts the module is emitted and well-typed. *Gate: `bun --filter '*' typecheck` + `test` green;
biome clean.*

**S6 — frontend routes + component (ts).** `src/routes/chronicle/index.tsx` (shows index, landing)

`ShowChronicleView` components in `src/domain/components/`; nav entry "Chronicle". Episode cards
link to transcript pages. SSR-safe (no client-only globals at module scope). Component smoke test.
*Gate: typecheck + test + build green; visually verify in a real browser (Playwright, ~5s wait).*

**S7 — deploy wiring.** Extend `linguist-commit` (`justfile:113` `git add` + `:134` redeploy grep)
