# orator-backend — the campaign's Discord music bot, its REST API and operator web UI

orator-backend is one Node 24 process that plays music into a Discord voice channel, imports tracks
(uploads and YouTube via yt-dlp), and serves a REST API plus a small operator SPA. The SPA is a
TanStack Router client app (not TanStack Start) under `src/web/`, Vite-built to `dist/` and served by
the same process. The Stream Deck plugin (`apps/orator/controller`) drives the same REST API.

It runs as the Compose service `orator-backend` on port 10363, behind Caddy at `orator.iridi.cc`, with
its library in the `orator-postgres` service (host port 10364). Config is the `orator` block in
`ontology/ontology-config/config.kdl`; there are no config env vars besides the SOPS secrets.

## Operations

- **Deploy:** push, then `just deploy orator-backend`. A plain `docker compose up -d` starts it with
  no secrets, and it refuses to start.
- **Data:** audio lives in `/ruby/data/astra-state/audio/orator` (container `/data`, config
  `orator.data-dir`), the library in `/ruby/data/astra-state/postgres/orator`. The audio is ingested
  at runtime and cannot be re-seeded; the nightly backup is the only other copy.
- **yt-dlp imports fail with HTTP 403 or "unable to download video data":** YouTube broke the pinned
  yt-dlp. Expect this every month or two.
  1. Set `ARG YT_DLP_VERSION` in `deploy/node.Dockerfile` (the `os-ffmpeg` stage) to the current yt-dlp release.
  2. Commit, push, `just deploy orator-backend`.
  3. Test inside the container with the exact flags from `src/media/ytdlp.ts`. The runtime image has
     no `curl`, so to try a newer release first, `docker cp` the binary in.
- **Stream Deck keys:** an operator mints an `orator_…` API key on the SPA's Keys page (needs a
  logged-in session). The controller can only use a key, never mint one.

## Traps

- **Startup fails closed.** orator refuses to start without a session secret of at least 32 bytes or
  with an empty operator allowlist. The allowlist is every `is_admin` player in `being.kdl` plus the
  optional `orator.allowed-user-ids` override (`src/allowlist.ts`).
- **The Discord bot is optional.** Without a resolved Discord token the web UI and library still run,
  but every playback route answers 503.
- **A new `orator` config key goes in two places, then `just ontology-gen`:** `config.kdl` and
  `OratorConfig` in `libs/py/config/src/astra_config/models.py` (required, no default). `just
ontology-gen` regenerates the TS Zod schema (`libs/ts/config/src/config.gen.ts`) from it; commit
  both. Python never loads `orator`, but the whole-file CI test (`test_whole_config_kdl_validates`)
  validates it against `OratorConfig`, and `ontology-check` fails CI on a stale Zod schema.
- **The schema is the numbered files in `migrations/`** (`libs/ts/pg-migrate`), applied at boot.
  Change it with a new file, never by editing an applied one: orator then refuses to start.
- **Most tests use `src/db/fake-store.ts`**, an in-memory double that can't catch wire-level SQL bugs
  (parameter types, array params, `bigint` columns coming back as strings). `src/db/store.pg.test.ts`
  runs the real store against a throwaway Postgres (`just pg-test`, the CI `pg-test` job); add a case
  there for any store change. Never point it at the live `orator-postgres`.
- **Table ids are `generated by default as identity`**, not `always`, so a migration can insert
  explicit ids and keep the collection and track foreign keys. After inserting explicit ids, reset
  the sequence past the highest id.
- **Voice needs the native `@snazzah/davey` module** (an optional dependency with prebuilt binaries;
  no compiler needed). If it fails to load, Discord closes the voice socket with code 4017.
- **The SPA serves its own fonts.** `scripts/gothicFontsPlugin.ts` copies the gothic fonts into
  `dist/fonts/` at build, because Caddy does not inject them for orator. The SPA reads its RUM
  endpoint from the public `/api/v1/rum-config` route, since a Router-only app has no server
  functions.
- **The HTTP layer is `@astra/service-kit`** (`src/server/app.ts`). Everything under `/api/` except
  `/api/v1/health` and `/api/v1/rum-config` is one authenticated route group: a request with no valid
  session or API key gets 401 before any route lookup, real path or not. Route bodies are zod schemas
  in the route modules (`src/server/bodies.ts`); their messages are the API error codes, and
  `src/server/pins.test.ts` pins every response. The compose healthcheck probes `/healthz`, which
  answers 503 while Postgres does not; on SIGTERM the server drains, then the bot leaves Discord, then
  the store closes.
- **Ingest progress is SSE.** The Caddy stanza disables buffering (`flush_interval -1`) on the job
  events path only; keep that if you touch the edge config.
