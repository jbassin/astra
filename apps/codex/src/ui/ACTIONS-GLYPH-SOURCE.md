# Action-glyph asset provenance (switched to the real font — see "Current implementation" below)

**Legal posture:** stakeholder-cleared on the record ("I've checked with our lawyers and we have
permission" — 0029 P6 scope doc, R5). Not re-litigated here; this file records only the technical
provenance the decisions require.

## Current implementation — the real Paizo "Pathfinder-Icons" font (stakeholder directive)

Stakeholder directive: "use the icons in pathfinder-icons.ttf for the action icons." `actionGlyph.tsx`
now renders the actual font at `apps/codex/public/pathfinder-icons.ttf` directly — a `<span>` carrying
one Private-Use-Area character, styled via a self-hosted `@font-face` in `globals.css` — instead of the
R5 traced-SVG-path implementation this file previously documented (kept below as a superseded record).

### Source

- **File:** `apps/codex/public/pathfinder-icons.ttf` (already present in the repo at the time of this
  switch — no new fetch).
- **Font metadata (from its own `name` table):** family `Pathfinder-Icons`, "Version 2.0", "Font
  generated by IcoMoon."; copyright "Paizo Incorporated, 2019"; designer "Jason Bulmahn and Sarah
  Robinson"; description "A symbol font for use with the 2nd Edition of the Pathfinder Roleplaying
  Game."; license "Pathfinder Compatability License" (`https://paizo.com/pathfinder/rpg/compatibility`).
  This is Paizo's own official compatibility icon font, distinct from the `foundryvtt/pf2e`-sourced
  `Pathfinder2eActions` font the prior SVG-trace implementation drew from (see "Superseded" below) —
  same visual vocabulary (action-cost pips/reaction hook/free-action diamond), different upstream asset.
- **unitsPerEm:** 1024; ascent 960 / descent −64 (`head`/`hhea`/`OS/2` tables agree).

### Codepoint → cost mapping (verified via `fontTools`)

The font ships a `GSUB` ligature table (`liga` feature, `latn` script) mapping bracketed name strings to
6 Private-Use-Area glyphs — the same convention IcoMoon-generated icon fonts commonly use for named
icon access:

| Ligature string     | Resolves to  | `ActionCost`  |
| -------------------- | ------------ | -------------- |
| `[one-action]`        | `U+E902`      | `"1"`           |
| `[two-actions]`        | `U+E901`      | `"2"`           |
| `[three-actions]`      | `U+E900`      | `"3"`           |
| `[reaction]`           | `U+E904`      | `"reaction"`    |
| `[free-action]`        | `U+E903`      | `"free"`        |
| `[uniE905][uniE905]`   | `U+E904`       | (unused — `uniE905` itself is a blank/empty glyph, 0×0 bounds; this second ligature isn't consumed anywhere in codex) |

`actionGlyph.tsx`'s `GLYPH_CHARS` map uses the raw `\uE9xx` codepoints directly (`""` etc.) rather
than relying on `liga`-substitution of the literal bracketed strings — a plain literal PUA character is
portable everywhere the string touches (SSR's `renderToStaticMarkup`, which has no font-shaping engine
at all, plain-text search extraction in `text.ts`, ...), where ligature substitution is a rendering-time
behavior that depends on the consuming engine supporting OpenType `liga` — unnecessary risk for zero
benefit here, since the codepoints are already known and stable.

Extraction method: `fontTools.ttLib.TTFont(...)['GSUB'].table.LookupList.Lookup[0].SubTable[0].ligatures`
— a `LigatureSubst` (`LookupType == 4`) keyed by first-glyph name, each entry pairing a full component
glyph-name sequence (spelling out the bracketed string, one glyph per character) with its `LigGlyph`.

### Pre-composed multi-action glyphs (no manual pip repetition needed)

Unlike the prior SVG implementation (which repeated ONE traced pip-chevron shape N times at a fixed
9-unit spacing to build the 2/3-action glyphs), this font ships `two-actions`/`three-actions` as their
own wider, pre-composed multi-chevron glyphs — advance widths scale accordingly (one-action/free/
reaction ≈ 1024 font units ≈ 1em; two-actions ≈ 1600 ≈ 1.56em; three-actions ≈ 2128 ≈ 2.08em), so normal
text layout produces correctly-proportioned glyphs with zero manual composition math.

### What changed vs. what didn't

- **Removed:** the 3 traced `<path>` shapes (pip chevron/reaction hook/free-action diamond) and their
  `<symbol>` entries in `GlyphDefs.tsx` (`GLYPH_IDS.pip`/`.reaction`/`.free` — deleted); `ActionGlyph`'s
  internal `<svg>`/`<use>`/`Pip` composition machinery (`actionGlyph.tsx`).
- **Unchanged:** the public contract every downstream call site (`statblock.tsx`, `facetHeader.tsx`'s
  `CodexActionGlyph`, `nodes.tsx`'s inline `actionGlyph` case, `columnDefs.tsx`, `text.ts`'s plain-text
  fallback) consumes — `ActionGlyph({cost})`'s prop signature, `normalizeActionCost`, the `ActionCost`
  type, and the `role="img"` + `aria-label` + hover-tooltip (`title` attribute now, was an SVG `<title>`
  child) accessibility contract. None of those call sites changed at all.
- **SSR/hydration:** the glyph is now a plain text character inside a `<span>` — server and client render
  byte-identical markup with no DOM/attribute diffing hazard (simpler than the prior SVG, which was also
  hydration-safe but via a different mechanism).
- **`EditionIcon.tsx` is UNTOUCHED** — the Remaster/Legacy pills stay inline-traced SVG (`GlyphDefs.tsx`
  still hosts those 2 `<symbol>`s); this switch is scoped to action-cost glyphs only, per the stakeholder
  directive's own wording ("action icons").

## Superseded record: the R5 traced-SVG implementation (D29-65)

- **Asset:** `static/fonts/pathfinder-2e-actions.woff2` — the system's own action-icon font
- **Tag fetched:** `pf2e-8.3.0` — the exact same release our existing Foundry snapshot
  (`data/snapshots/foundry/pf2e-8.3.0/`) already pins, so the glyph shapes matched the corpus's own
  action-cost data vintage exactly
- **Commit:** `bebe55ad9f5e0b7184fd019bc1e410fdbb2e934e`
- **Fetch URL:**
  `https://raw.githubusercontent.com/foundryvtt/pf2e/pf2e-8.3.0/static/fonts/pathfinder-2e-actions.woff2`
- **Fetch date:** 2026-07-15
- **Fetched file SHA-256:** `235ad1a4540736c4521e07d5c8d3445b68dbe1398e8b32b7d7a5b2551a15fcee`
- **Font metadata (from its own `name` table):** `Pathfinder2eActions`, "Version 001.000",
  "FontForge 2.0 : Pathfinder2eActions : 23-9-2019" — a hand-built icon font, not a generated one

### Codepoint → cost mapping (cross-checked against the system's own source)

The pf2e system's `getActionGlyph()` helper (`src/util/misc.ts`, same `pf2e-8.3.0` tag) maps an
action cost to a single character rendered in this font:

| Cost       | Character | Font glyph name (from the font's own `cmap`/`post` tables) |
|------------|-----------|--------------------------------------------------------------|
| 1 action   | `"1"`     | `one` (identical outline to glyph `A`/`a`)                    |
| 2 actions  | `"2"`     | `two` (identical outline to glyph `D`/`d`)                    |
| 3 actions  | `"3"`     | `three` (identical outline to glyph `T`/`t`)                  |
| Free       | `"F"`     | `F`/`f` (identical outline to glyph `four`)                   |
| Reaction   | `"R"`     | `R`/`r` (identical outline to glyph `five`)                   |

(The font ships digit-glyphs and letter-glyphs as literal geometric duplicates of each other —
verified via `fontTools`' `BoundsPen`, matching advance widths and contour counts pairwise — so
either codepoint traces to the identical outline; the mapping above is the one the system's own
code actually emits.)

### Glyphs pulled (the 5 `ActionCost` values `actionGlyph.tsx`'s type already names)

- **One action** — glyph `one` (≡ `A`) → `PIP_PATH_D` in `actionGlyph.tsx`, reused 1–3× for the
  1/2/3-action counts (the file's own pre-existing composition scheme, unchanged by this swap).
- **Two/three actions** — NOT pulled as separate composite glyphs (`two`/`three` exist in the font
  as wider multi-pip-in-one-glyph shapes, but `actionGlyph.tsx`'s existing design repeats the
  single one-action pip glyph N times at a fixed spacing rather than embedding N distinct
  pre-composed glyphs — kept as-is per D29-65's "pure asset swap" instruction; only the pip's own
  outline is real-traced, not the multi-pip composition).
- **Reaction** — glyph `R` (≡ `five`) → `REACTION_PATH_D`.
- **Free action** — glyph `F` (≡ `four`) → `FREE_PATH_D`.

### Conversion (one-time, offline — no runtime font dependency added)

1. Decoded the WOFF2 → glyf outlines with `fontTools` (`TTFont`, Python; `brotli` extra for WOFF2
   decompression).
2. For each of the 3 glyphs pulled, computed its native bounding box (`BoundsPen`) and built an
   affine transform (uniform scale + Y-flip, since TrueType is Y-up/font-units and SVG is
   Y-down/pixels) mapping that bounding box onto a small integer-ish coordinate space matching
   `actionGlyph.tsx`'s existing viewBox conventions: the pip → x:0–7.5,y:3–13 (the exact box the
   old placeholder triangle already occupied, so the `count * 9 + 1` / `i * 9 + 1` composition math
   needed zero changes); reaction/free → x:2–14,y:2–14 inside the existing `0 0 16 16` viewBox.
3. Drove `fontTools.pens.transformPen.TransformPen` wrapping `fontTools.pens.svgPathPen.SVGPathPen`
   with that transform, so the font's own quadratic-curve emission (including TrueType's
   "implied on-curve point" contours, e.g. the reaction hook) is handled by fontTools itself, not
   hand-rolled — avoids the curve-segment bugs a naive point-flattening approach hits.
4. Coordinates rounded to 2 decimal places for a compact `d` string.
5. Visually verified each path by rasterizing to PNG (`cairosvg`) before pasting into the
   component — the pip renders as the expected concave chevron, free as a diamond with its
   characteristic notch cutout, reaction as the hooked circular arrow — all recognizable as the
   real pf2e action icons, not the prior placeholder approximations (a plain triangle, an
   unfilled diamond outline, a hand-drawn hook).

No font-to-SVG conversion tool was a runtime/build dependency at the time — this was a one-shot script
run locally, and only the resulting `d` attribute strings were committed (`actionGlyph.tsx`). That
committed path data is now GONE (superseded by the current implementation above); this section
documents provenance only, not the current state of the file.

### Why SVG-not-a-font, at the time (superseded reasoning)

The R5-era `actionGlyph.tsx`/`EditionIcon.tsx` comments both noted "icon fonts blank out in rasterized
PNG export" as the reason to prefer inline SVG over a font. That constraint doesn't apply here: codex has
no PNG-export path of its own (unlike `vellum-render`, the Playwright-based PNG service some of that
inherited wording referred to) — codex is a plain SSR website, and the current implementation's glyph
characters render identically server- and client-side as ordinary text. `EditionIcon.tsx` still uses
inline SVG (untouched by this switch), so that file's own comment referencing "the same reasoning
`actionGlyph.tsx` already documents" is now stale for the action-glyph side specifically — recorded here,
not chased as a live bug.
