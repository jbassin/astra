## What 0009 is

Rewrite faerrin's `mouth` (Rust dice/host Discord bot, 3 crates) into astra's **weal-bot** (TS/Bun Compose
service) and lift faerrin's `eerie` into **weal-overlay** (Compose service). The crux + #1 risk is the
**roller rewrite**: a pure dice-DSL (Pratt parser → AST → eval, ~1100 LOC across `roller/src`) ported to TS

**astra's first long-running TS/Bun service** (strider is a frontend SSR server; this is a Discord-gateway +
internal-API service), so it also establishes the bun-service conventions.

## The roller (the crux) — structure + the parity surface

Pure, **no I/O**, seeded `StdRng`. `roll(text, init, rng) → Result<Res,String>` where
`Res { to_roll: Vec<Roll>, to_plot: Vec<Plot>, to_roll_lazy: Vec<Lazy>, to_save: Vec<Save> }`. Pipeline:
`parse(str) → Expr` (nom + `pratt` crate) → `eval(Expr, Context) → Cmd {display, plot, lazy, save}` →
`display_to_roll` materializes `Display::Die` into `RollDie {value,max,min,dice:[(base,face)],reroll}` by
sampling the RNG.

**Language surface to port faithfully (K6 hand-port):**
- Atoms: numbers (`1_000_000` underscores), dice `d20`/`8d6` (also `D`), seq dice `d{1,2,3}`, idents
  (`lower-alpha` + `[alnum-]`, **`let`/`in` reserved**), sigils `:name`, lists `[a,b,c,]` (trailing comma
  ok), func-calls `f(a,b)`, anon funcs `|a,b| body`, named funcs `let f(a,b)=… in …`.
- Operators (pratt precedences in `pratt_parser.rs`): `;`(1,L) `+ -`(3,L) `* /`(4,L) `.`(5,R dot-call
  sugar: `x.f(y)` ⇒ `f(x,y)`) unary `-`(prefix 6). `BinOpr::modify`: `Semi`→rhs, `Dot`→lhs, int `/` is
  **truncating**.
- Builtins (`ast.rs::dispatch_builtin`): `d, id, take-highest, take-lowest, roll, plot, lazy-roll, save,
  max, min`. List-broadcast semantics in `mod_bin_op` (op distributes over `List`; Die⊕Number lifts Number
  to `Die::Constant`). Closures capture by `captured_idents` (lexical pruning).
- `Die` variants: `Constant, Base(count,base), Seq(count,vals), BinOp, TakeHighest, TakeLowest`. Carries
  `possibilities()→Counter` (exact distribution), `min()/max()`, `repr()`, and `value(rng)→DieRes`
  (the random surface, with the `⟪…⟫` repr formatting + `__**bold**__` for kept dice).

**Parity harness (K1) — gate the deterministic surfaces, NOT raw RNG output** (Rust `StdRng` ≠ any TS RNG):
1. **parse**: input → AST, exact. Golden vectors **already exist** in `parser.rs` tests (serde s-expr via
   `serde_lexpr`) and `eval.rs` tests (Rust `Debug` of `Cmd`). Extract these as the seed corpus.
2. **eval given injected die faces**: make face values deterministic (inject a sequence instead of `gen_range`)
   and compare `value`/`repr`/`dice`. Requires a seam in both impls to feed faces (Rust samples in
   `Die::value`; the TS port must expose the same injection point).
3. **plot math**: `Die::possibilities → counter_to_prob (sorted (val,prob)) + avg + std`, exact float compare
   (population std; `avg`/`std` over the *expanded* multiset via `counter_to_iter`).
4. **property tests**: every rolled value ∈ `[min,max]`; `take-highest`/`-lowest` count guards; error cases
   are `Err` (→ bot no-op). Generate random expressions, assert invariants on both impls.

**Two latent behaviors the port must consciously decide (not faithfully copy by accident):**
- **`host_says` only ever picks GSR.** `Distribution<HostPicker> for Standard` is hardcoded to return
  `HostPicker::GSR` (`host.rs:198`), so `OsRng.sample(Standard)` is always GSR — the Rex/Els/Whiskers
  flavor-line banks are **dead code today**. See K8.
- **The displayed "seed" is cosmetic.** `SeedInfo.seed = rand::random()` but rolls use
  `StdRng::from_entropy()` (`handler.rs:710`) — the seed never seeds anything; `reseed` is theater. See K10.

## weal-bot — the service (message flow, verified in `handler.rs`)

discord.js gateway, intents incl. **MESSAGE_CONTENT** (privileged). On each non-bot message:
`trim` (strips ` ``` ` / `ocaml` code-fences) → `parse_func` regex `^\s*(name)\((args)\)\s*$`:
- `reseed()` → cosmetic Knife message + new (unused) seed.
- `plot(base, interval)` → **historical** dice chart (the `chart` crate → `chart.iridi.cc`). **K4: DROP** —
  this command + `get_dice`/`dyn_plot` + the analytics query (`player_id <> 6` read-time filter) **do not
  port to weal-bot**; distribution viz over history is akasha-frontend's job (0011). ⚠ Note: this is a
  *different* "plot" from the **in-roller `plot(d20)` builtin** (probability of a single expression), which
  **stays** in the roller (`to_plot`).
- otherwise → `roller::roll`. **Parse/eval error = silent no-op** (`Control::Cont`, return Ok). For each
  `Roll`: `Roll::Number` → a Knife "i invented the number" message (no save); `Roll::Die` → save to DB
  (with guards) → `host_says` (host+flavor by `RollGoodness`) → **webhook send** (per-host
  `username`+`avatar`+`color` embed, K2) → **best-effort** dice-feed (Discord feed webhook + v1 POST to
  overlay). `RollGoodness` (`goodness.rs`): value==min→Fumble, ==max→Crit, else thirds of
  `[min,max]`→Bad/Okay/Good. Class→thumbnail map (PF2e AoN URL / D&D imgur per class) is identity-adjacent
  presentation lifted with the host send.

**Internal speak API** (`http.rs`): `POST /api/v1/speak {host,guild,channel,message,img?}` on `bind-addr`
(`127.0.0.1:10203`, internal only — the control plane mike's overlay/orator dial). Port as `Bun.serve`.

**Webhooks**: auto-discovered/created per text channel at `cache_ready` (one `faceless-host` webhook per
channel), keyed `guild→channel→Webhook`. The dice-**feed** webhook is `dice_feed_url` (the rotated secret).

**Data (Postgres, Decision F)**: 2 tables (`migrations/0001_init.sql`): `dice(id, base, value,
source='discord', timestamp, player_id, blame_id)` + index `(base,timestamp)`; `funcs(id, name, payload)`.
**Save guards stay in the bot** (`save_die`): skip pools >30 dice, skip any die with `base>100` (still
rolled+shown, just not persisted) — these prevent *new* junk; they are NOT a migration filter.

strider's TanStack SSR template — see K7.

## The migration claim, corrected against the live DB

The plan §2.3 / risk-3 frame the migration as "47M+ rows, exclude junk (`player_id<>6`, `base≤100`,
`pool≤30`)". **Verified against the live `pkg/mouth/mouth.db`: that framing is stale.** The live source is
**8,931 dice rows + 10 funcs** (player_ids 1–6; `player_id=6` = 15 rows, S.C.H.I.S.M.; no `base>100`; range
2023-06 → 2026-06-19). The 47M-row `d123456789` mega-roll was **already excluded** when faerrin did its own
**Postgres→SQLite** cutover (`scripts/migrate-to-sqlite.ts` excludes `base=123456789`). astra's Decision F
is the **reverse direction (SQLite→Postgres)** — so it's a tiny, already-clean copy needing a *new* script,
not the old one. The three "filters" in the plan are actually three different mechanisms:
- **save-guards** (`MAX_POOL=30/MAX_BASE=100`) → prevent *new* junk; **keep in the TS bot**.
- **`player_id<>6`** → a *read-time analytics* filter (plot labels), NOT a migration delete; row stays.
- **`base=123456789`** → the actual migration exclusion (already applied; absent from the live file).

So: preserve `player_id` verbatim, copy all ~8.9k rows, keep the save-guards live. This is **Phase-6
cutover** work (config annotates `dice_feed_url` "resolved at cutover"); for 0009 the schema + a verified
copy path is enough.

## Exit criteria (from plan §6)

- **Roller parity harness green** (parse/eval-given-faces/plot/property match the Rust golden vectors) —
  only then is the Rust retired.
- weal-bot (Compose) reads a dice message → rolls → posts as a host (webhook) → records to Postgres →
  drives weal-overlay (v1); survives a container restart + Discord WS drop.
- Roll history copy path verified: `player_id` preserved, counts match, save-guards active (execution = P6).
- weal-overlay renders a live roll (SSE) with OBS reconnect; v0 removed; gothic styling applied.
- Host identities from `ontology-being weal-host`; no plaintext secrets; leaked webhook rotated (P6).

## Risks (from plan §7, sharpened)

1. **Roller correctness (#1).** A subtle parse/eval divergence corrupts every roll. Mitigation: the K1
   deterministic-surface harness as a hard gate; keep the Rust runnable until green. Watch: truncating int
   `/`, list-broadcast, dot-call sugar, closure capture, `let`/`in` reservation, `possibilities()` blow-up
   on big pools (guard the plot path).
2. **RNG not golden-comparable** — only deterministic surfaces are; cover the random path with property tests
   (range/guards) + a seeded-distribution sanity check, not exact-output parity.
3. **`player_id` integrity** — load-bearing FK; never renumber; verify counts post-copy (≈8,931, not 47M).
4. **Webhook hygiene** — `dice_feed_url` leaked in faerrin git history; rotate at cutover, SOPS-only, never log.
5. **discord.js as a long-running Compose service** — reconnect/backoff + MESSAGE_CONTENT intent; validate it
   survives restarts + WS drops (Phase-4 service shakedown). weal-bot is the first bun *service* — its
   Dockerfile/healthcheck/restart wiring is a new template (no prior bun-service unit in compose).
