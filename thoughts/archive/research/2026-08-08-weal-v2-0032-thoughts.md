## 1. What v1 is (compressed) and what carries forward

v1: scannerless recursive-descent parser + Pratt climber → tiny untyped functional language
(closures, `let…in`, lists, sigils) where dice are **symbolic values** combined lazily into trees,
materialized at display; 10 builtins; saves = serde-JSON ASTs in Postgres `funcs`; every guild
message is a roll candidate; failures silent; distribution math = exponential cartesian enumeration.

**Carries forward (as concepts):** every-message-is-a-candidate classification + code-fence trim ·
dice-stay-symbolic-until-display (this becomes the render tree) · saves seeding the evaluation env ·
per-die persistence with pool/base guards · goodness driving host flavor · cosmetic seed ·
overlay/dice-feed broadcast. **Dies:** the v1 AST/serde format (funcs table content does NOT
migrate), `;`-as-sequence / `.`-method-sugar / `in`-keyword syntax, the exponential
`diePossibilities`, silent eval errors, `plot`/`lazy-roll` vestiges, the TS roller itself.

## 2. Language definition (as converged — R-refs in §6)

### 2.1 Lexical
- Comments `(* … *)` anywhere, nestable (spec: confirm nesting; OCaml nests — lean yes).
- Insignificant whitespace. Identifiers `[a-z][a-zA-Z0-9_]*` (NOTE: underscores, not v1's kebab).
- Atoms `:atom`, `:kebab-case` (kebab allowed in atoms per the musings' own example).
- Literals: Num `1`, `1_000` (arbitrary precision); Dec `1.0`, `0.100_120` (fixed-point,
  **19.6 = 19 integer digits, 6 fractional; i128-scaled 10^6** — interpretation, veto-able);
  Float `1.0f`; Str `"unicode"`; Unit `()`.
- Die literals `d20`, `2d6`, case `d` only (drop v1's `D` — spec call, lean lowercase-only for
  suffix-lexing sanity).

### 2.2 Types (strict, inferred, no user-defined generics)
`Unit · Num · Dec · Float · Str · Atom · Tuple{…} · List[T] · Dict[K,V] · Die[T] · Pool[T] ·
functions (curried, `A -> B`)`.

- **Singleton-atom unions (R14):** `:fire` has singleton type `:fire`; finite unions of atom
  singletons are internal checker machinery; **`Bool = :true | :false`** is a predefined alias
  (users cannot declare aliases). Join = set union (bounded by source size); subsumption =
  one-directional subset widening (`:fine ≤ :fine|:good ≤ Atom`). `match` over a
  singleton/union scrutinee is exhaustiveness- AND redundancy-checked (missing arm = error;
  pattern not in the set = unreachable error → catches `:ture` typos). Match over plain `Atom`
  requires a wildcard arm. Errors print `Bool` for exactly `{:true,:false}`, else the union.
- **No implicit numeric mixing (R6):** Num/Dec/Float convert only via explicit prelude functions.
  Dec is the display/probability-presentation type; engine probabilities are exact integer weights
  (§4).
- **Comparisons** `> >= < <= == !=` : `Num -> Num -> Bool` (and per-type analogues) returning
  `:true|:false` (R5).
- Functions: exactly-one-input curried; `foo(x, y) = …` and call `foo(1, 2)` are sugar; partial
  application is legal and typed. Anonymous: `|a, b| body` and call-position placeholder
  `twice(_ * 2, 3)` (spec: placeholder scope rule — lean Scala-style "each `_` is a fresh param of
  the smallest enclosing argument expression"). Closures capture environment (by value; language is
  immutable).

### 2.3 Bindings, match
- Expression language. `let x = e1; e2` — **`;` is OCaml's `in`** (R12): it terminates the binding,
  the trailing expression is the result. Chaining nests naturally. NOT v1's sequence operator.
- Sugar: `let foo(x, y) = …;` ≡ `let foo = |x, y| …;`. Tuple destructuring `let {x, y} = {1, 2};`.
  Optional annotation `let x Num = 1;`.
- `match e | pat -> e' | …` with literal/atom/tuple-destructure/wildcard-or-binder patterns.
  No guards in v2.0 (nest a match on a comparison's Bool instead) — spec-sanctioned deferral.

### 2.4 Dice, pools, labels, suffixes
- `NdM` / `dM` : uniform numeric faces. `dl([…])` : equal-weight faces from a list — **faces may be
  atoms**; face order = list order. `dm([f: w, …])` : weighted faces; face order = dict literal
  insertion order (R15). `Die[T]` is generic; T is the face type (incl. atom unions → matching on
  an outcome is checked against exactly the die's faces).
- **`Pool[T]` is first-class (R16, forced by user evaluators):** `pool(n, die) : Pool[T]`. The
  literal `4d6` in ordinary position denotes the summed `Die[Num]`, but **lowers through a pool**:
  `4d6kh3` lowers at parse time to `kh(pool(4, d6), 3)`. **Die-suffixes are functions on pools** —
  `Pool[T] -> A -> Die[T]` (or `-> Pool[T]` for chainable ones) — amending the musings' `Die -> T ->
  Die` (keep-highest on an already-summed distribution is not computable). Suffix chains lex
  greedily (`[a-z]+` + optional Num after a die literal), resolve at **type-check** (unknown suffix
  = type error, not parse error), lower left-to-right (R8).
- **Labels (R13):** `2d8[fire]`, `(2d8 + 4)[slashing]` — postfix bracket with a bare word on any
  die-typed expression; annotates the render tree (≈ `label(die, :fire)`). Composes with the render
  collapse policy (§5.2).
- Arithmetic: die⊗die, die⊗num stay **symbolic** (render tree) with the distribution computed via
  the engine's binary-op product. Mixing dice with unequal denominators uses icepool's
  `weighted_lcm` construction (§4).
- **User-supplied evaluators (R17):** `evaluate(pool, init, |state, outcome, count| …) -> Die[S]` —
  the icepool transition-function contract surfaced as a weal closure. Evaluator closures must be
  effect-free (checker rejects effectful builtins inside them). Joint multi-pool (opposed/RISK)
  evaluators are **out** for v2.0 (R18).

### 2.5 Effects & top level
Top-level result displays like v1 (numbers, dice → rolled; Unit/closures silent). Effectful
builtins: `roll(…)` (extra displays), `plot(die)` (chart output, §5.3), `save(:name, value)`
(§5.5). Effect typing mechanism (simplest: effect-marked builtins legal only outside evaluator
bodies) is a spec detail. Prelude dice ops per R25: `explode` (depth-capped), `successes`,
`reroll` — all die-level substitutions or tiny built-in evaluators (§4 skip-list's `Again`/Markov
generality is still skipped; bounded explode is the simple weighted-expansion form).

## 3. Engine: Rust → WASM

- **Rust, compiled to `wasm32`, loaded by the existing Node bot at startup** (R1). weal-bot runs TS
  directly under Node (`nodeTsResolve` hook, no bundler — verified `apps/weal-bot/package.json`);
  the engine is a file the bot `WebAssembly.instantiate`s (wasm-bindgen, node target). No new
  runtime container; Dockerfile gains a COPY. This amends the two-toolchain charter: Rust is
  confined to the engine crate + its build. Crate home + build story = **O1/O2 (open)**.
- Tokenizer **logos**, CST **rowan** (stakeholder-specified). Typed AST lowered from the CST;
  type checker (HM-style + the atom-union lattice); tree-walking evaluator over immutable values.
- **RNG seam stays host-side / injected** (like v1's `RollRng`): wasm imports an entropy function;
  tests inject deterministic faces. Seed remains cosmetic UI (R11).
- **Fuel budget is a hard requirement (R19):** user evaluators + exact distributions can blow up
  (v1 happily rolled `10000d10000`). The engine meters work (transitions, state-map size, bigint
  digits) and aborts with a visible "too expensive" error — never a hang.
- **Re-entrancy:** the DP loop calls back into the interpreter for user evaluator closures.
  Memoization keys = (room, state) with weal-value structural equality/hashing — works because all
  values are immutable.

## 4. Icepool port scope (verified against paper + v2.2.2 source)

**The algorithm (paper):** a mechanic = one incremental pass over the sorted outcome sequence
grouped by outcome — `next_state(state, outcome, count)`; DP over (die-suffix, pool-size) with
memoization; `k`-of-`n` dice hitting an outcome weighted `C(n,k)·w^k` via a weighted Pascal
triangle; call-graph edges Θ(ℓ·n²); weights are **exact arbitrary-precision integers** (implicit
denominator = total weight; probabilities derived at the end).

**Port (≈400–500 lines of load-bearing logic, from the source inventory):**
1. Die repr: `BTreeMap<Face, Weight>` (sorted faces, integer weights) + cached denominator +
   explicit GCD `simplify` (icepool `Counts`, `Population`).
2. Binary/unary ops: cartesian product accumulating `w_l·w_r` (icepool `Die.binary_operator`,
   ~50 lines); comparisons collapse to 2-outcome `Die[Bool]` immediately.
3. `weighted_lcm` mixture construction for unequal denominators (~30 lines).
4. The pool recursion: pop-extreme-outcome + per-die binomial `comb_row` expansion + **keep-tuple**
   (one int per sorted position — kh/kl/drop/middle/negative all one mechanism, port as-is) +
   memo per room; **keep the two cheap optimizations**: `skip_weight` all-remaining dump when the
   keep-tuple empties, and direction choice by which end has more zeros (`lo_hi_skip`).
5. Keep-1 closed forms (cumulative-power / product-of-cumulatives) bypassing pool machinery for
   min/max/highest-of — cheap, most common case.
6. Mean/std as exact rationals → Dec/float at the edge (numeric faces only; symbolic faces have
   distributions but no mean).

**Skip:** the expression DAG / dungeonlet layer (~4k lines of generality), Deck/Deal
(hypergeometric), `Again`/Markov machinery, `Vector`/`Symbols` outcome types, `DieWithTruth`,
forward-order negotiation beyond the two heuristics above, `can_truncate` (optional polish — only
mixed-size standard-dice pools; revisit if the prelude grows a mixed-pool constructor).
**Weights:** `u128` fast path with checked-overflow promotion to bigint (`num-bigint`) — 10d20's
denominator fits u64 but compositions overflow fast; bigints are mandatory as the slow path.

## 5. Bot surface

### 5.1 Classification & errors (R9)
Every rostered-player guild message is still a candidate; code-fence/`ocaml` trim unchanged;
`reseed()` special-case unchanged. **Parse failures stay silent** (chat noise). **Messages that
parse but fail type-check get a visible error reply** — the new "macros are debuggable" surface.
Eval-time errors (fuel, div-zero) on something that parsed+checked: also visible (it was
definitely meant as a roll).

### 5.2 Roll rendering (the headline UX change)
Dice stay symbolic through evaluation → a **render tree**: leaves = die literals (faces attached
at sample time, `2d6 ⟪3,5⟫`), nodes = operators/suffixes/labels/function applications. Concision
is a **render policy** over the tree, not an encoding: collapse die-free subtrees to their value;
show named calls as `name(…)` with only die-bearing args expanded; labels name subtrees
(`2d8 ⟪3,7⟫[fire] + 1d6 ⟪2⟫[slashing] = 12`). Exact embed layout + collapse depth = spec-time;
the goodness→title/footer/flavor plumbing stays (5-tier thirds by face position, R24). Atom-faced outcomes render the
atom; overlay payload shows the atom as the value (R10); embeds for atom rolls skip numeric-only
furniture as needed.

### 5.3 Plotting (R7)
`plot(die)` renders the exact PMF as a chart PNG **in-engine via `plotters`** (pure Rust, works
under wasm targeting an in-memory bitmap + PNG encode) and the bot attaches it to the embed. Zero
new services. Mean/std in the embed text from §4.6. (K4's "viz moves to akasha" was about
*historical* rolls — per-roll plots live here.)

### 5.4 Persistence (R20)
Only scripts that resolve in an actual **roll** (not plot-only) persist; only **standard `NdM`
dice** rolled within them write `dice` rows (`base`, `value` — table unchanged, v1 guards
MAX_POOL=30 / MAX_BASE=100 kept); weird dice (dl/dm/atom-faced) are not persisted.

### 5.5 Saves / prelude (R2, R21)
Ships a **prelude** (kh, kl, min, max, label, evaluate, pool, dl, dm, conversions, … — contents
= **O4**) preloaded into every context. `save(:name, value)` extends it per-guild as v1 did, but
the stored payload is **source text**: values serialize by pretty-printing (every v2 value has a
literal form; closures print as `|params| body` with captured bindings emitted as enclosing
`let`s, recursively — capture-by-value materialized as source). Load = normal parse + type-check;
the save embed shows readable source. v1 `funcs` rows do not migrate (sanctioned).

## 7. Risks
- **Checker scope creep** — HM + atom-union lattice + currying is the largest single build item;
  the spec must pin the inference feature set hard (no user aliases, no recursive types, no row
  polymorphism).
- **Re-entrant WASM ↔ interpreter loop** — evaluator callbacks inside the DP hot loop; design the
  boundary so the *interpreter lives inside the wasm module too* (single crate: parse+check+eval+
  distributions all in Rust; JS only feeds source text + entropy and receives render/plot/save
  outputs). This dissolves the callback-across-boundary problem entirely — flag as the intended
  architecture.
- **Fuel calibration** — pick budgets from real macro workloads; err generous with a hard wall.
- **Charter amendment** — record the Rust lane in CLAUDE.md/CONTRIBUTING when built (O1 decides
  its CI shape).
