> Goal: rewrite faerrin's `mouth` (Rust dice/host Discord bot) into astra's **weal-bot** (TS/Bun) and

## 1. Current state (faerrin)

**`mouth`** (Rust, Cargo workspace, 3 crates):
- **`roller`** — pure dice-DSL: Pratt parser → AST → eval. `roll(text, init, rng) → Res { to_roll,
  to_plot, to_roll_lazy, to_save }`. `Roll = Number | Die` (Die carries `value/max/min/dice[]/reroll`).
  Supports dice + arithmetic + lists + **named lazy rolls** + **saved macros** (`to_save` → `funcs`) +
  **distribution plots** (`Plot {prob, avg, std}`). Seeded `StdRng`. ~1700 lines + tests. **No I/O.**
- **`discord`** — serenity gateway + axum control plane (`127.0.0.1:10203`, **internal only**) + SQLx.
  Every message → `roller::roll`; a parse/eval failure is a **silent no-op**. A `Die` result picks a
  host + a goodness-appropriate flavor line (`host_says`) and posts it.
- **`chart`** — dice-distribution **chart-URL builder** (external `chart.iridi.cc`).
- **Hosts** (`host.rs`): 6 NPC personas (GSR/Knife-That-Teaches/Rex Panopticum/Els/Whiskers/MasterOfCeremonies)
  + Custom, each `{name, image (imgur), color}`; **sent via Discord WEBHOOK** (`ExecuteWebhook` with
  `username`+`avatar_url` override). Hundreds of in-character flavor lines per host × roll-goodness.
- **Send API:** `POST /api/v1/speak {host, guild, channel, message, img?}`.
- **Roll→overlay:** best-effort `reqwest` POST to `FEED_WS_URL` + `X-Eerie-Token`, **v1**
  `{v,user,expression,total,value,is_crit,is_fumble}`.
- **DB:** SQLite (now), 2 tables: `dice(id, base, value, source, timestamp, player_id, blame_id)` +
  index; `funcs(id, name, payload)`. **Save guards** `MAX_POOL=30`/`MAX_BASE=100` exclude the 47M-row
  junk; analytics exclude `player_id<>6` (S.C.H.I.S.M.). `player_id` is the stable dice FK.
- Identity from `players.toml` (→ ontology-being).

**`eerie`** (→ weal-overlay): Vite+React+pixi SPA + `Bun.serve` SSE hub + ingest; `connectFeed`
EventSource with OBS-aware reconnect; accepts v0+v1 (`schema.ts`); does no dice logic.

## 2. weal-bot (astra, TS/Bun, Compose service)

discord.js gateway: message → **TS roller** → `Die` result → pick host + flavor → **webhook send** →
record to **Postgres** → POST **v1** to weal-overlay. Plus the internal **speak API** (`Bun.serve`).
Tokens/secrets from ontology-config (SOPS); host **identities** from ontology-being (weal-host type).

### 2.1 The roller rewrite (Decision B — crux, #1 risk)
- **Port** the Pratt parser + AST + eval to TS, faithful to the Rust structure (K6). Replicate: dice,
  arithmetic, lists, lazy rolls, saved macros, distribution math, reroll.
- **Parity harness FIRST** (before deleting Rust). ⚠ The roller uses a **seeded RNG** whose sequence
  differs between Rust `StdRng` and any TS RNG — so **don't compare raw random output.** Compare the
  **deterministic surfaces** (K1): (a) **parse**: input → AST (exact); (b) **eval given injected die
  faces** (deterministic); (c) **distribution/plot math** (`prob/avg/std`, exact); (d) **property
  tests** (every value ∈ `[min,max]`, pool/base guards, error cases = no-op). Extract Rust test vectors
  + generate cases as the golden set; run both impls; the harness is the gate.

### 2.2 Discord + hosts
- discord.js gateway; message listener → roller; silent no-op on non-rolls.
- **Hosts via webhook** (K2 — confirmed): per-host `username`+`avatar`+`color`. Host **identities**
  (name/image/color) ← ontology-being (weal-host); the **flavor lines** (host × goodness) live in
  weal-bot data (K5). `host_says` picks host + line by `RollGoodness`.
- **Speak API:** `POST /api/v1/speak {host, guild, channel, message, img?}` on an internal bind.
- **Roll→overlay:** v1 POST to weal-overlay (URL + token from ontology-config).

### 2.3 Data (Postgres, Decision F)
- `dice` + `funcs` SQLite→**Postgres**. **Preserve `player_id`** (the stable FK; 47M+ rows of history).
- **Migrate excluding the junk** (`player_id<>6`, `base≤100`, `pool≤30`) — faerrin already has the
  exclusion logic (`scripts/migrate-to-sqlite.ts`); re-apply on the PG cutover.
- Keep the save guards (`MAX_POOL`/`MAX_BASE`) in the TS bot.

## 3. weal-overlay (astra, TS, Compose service) — LIFT

## 6. Exit criteria

- [ ] **Roller parity harness green** — TS parse/eval/plot/property match the Rust golden vectors; only
      then is the Rust retired.
- [ ] weal-bot (Compose) reads a dice message, rolls, posts as a host (webhook), records to Postgres,
      and drives weal-overlay (v1) — survives a container restart.
- [ ] Roll history migrated to Postgres: **junk excluded**, **`player_id` preserved**, save guards active.
- [ ] weal-overlay renders a live roll (SSE) with OBS reconnect; v0 schema removed.
- [ ] Host identities from ontology-being (weal-host, distinct from podcast personas); no plaintext secrets;
      leaked webhook rotated.

## 7. Risks

1. **Roller correctness** (#1) — a subtle eval/parse divergence corrupts every roll. Mitigation: the
   deterministic-surface parity harness (K1) as a hard gate; keep Rust runnable until green.
2. **RNG can't be golden-compared** — only the deterministic surfaces can; cover the random path with
   property tests (range/guards) + a seeded-distribution sanity check, not exact-output parity.
3. **player_id integrity** — 47M+ rows hinge on the stable integer FK; never renumber; verify counts
   post-migration (minus the excluded junk).
4. **Webhook hygiene** — the `DICE_FEED_URL` webhook leaked in faerrin git history; rotate at cutover,
   store via SOPS, never log it.
5. **discord.js gateway as a long-running Compose service** — needs reconnect/backoff + the message-content
   intent; validate it survives restarts + Discord WS drops (Phase 4 service shakedown).

## 8. Hand-off

weal-bot's roll history (Postgres) feeds **akasha-frontend**'s dice dashboard / roll-probability insights
(the K4 viz home). weal-overlay consumes weal-bot's v1 roll POST. Host identities live in ontology-being
(weal-host), shared with anything that sends as a host.
